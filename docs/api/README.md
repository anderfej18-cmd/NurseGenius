# Server function API

The web app is the only client, so the API is TanStack Start **server functions** (typed RPC) rather
than hand-written REST routes (project convention, `AGENTS.md`). Each function lives in
`src/functions/<domain>.functions.ts`; the browser imports it and calls it like a function:

```ts
import { startExamSession } from "@/functions/sessions.functions";
const { examId, totalQuestions } = await startExamSession({ data: { examType: "RN", category: "All Areas", count: 20, minutes: 30 } });
```

The wire path is generated by the framework (`/_serverFn/<id>`) and is not a stable public URL, so the
docs identify each endpoint by function name and use `POST` for all of them.

## Conventions

| Topic | Rule |
|---|---|
| **Authentication** | Every function uses `requireSupabaseAuth`: the browser attaches the Supabase access token (`attachSupabaseAuth`), the server verifies it and exposes `context.userId`. No token or an invalid token → `401`. |
| **User identity** | Always `context.userId` from the verified token. No request field can name another user; schemas are `.strict()` so extra fields are rejected. |
| **Authorization** | Student functions touch only the caller's rows (every query filters by `user_id`). Admin functions call `is_any_admin` first → `403` for everyone else. |
| **Validation** | zod schema per function (`src/functions/*.schemas.ts`), applied through `validated()` before the handler. Failure → a `ValidationError` (`code: "VALIDATION_ERROR"`) listing up to three field problems, never the raw zod error. Services re-check business rules. |
| **Errors** | Typed `AppError`s carry a safe message, a `code` and a `statusCode`. Unexpected failures are logged on the server and replaced by `"Something went wrong. Please try again."` (no database text, ids or stack traces). **Transport:** TanStack serialises a thrown error to the browser, where the call rejects with an `Error` that has `message`, `code` and `statusCode`; the HTTP status of the underlying response is 500 whatever the error. Read `error.code`, not the HTTP status. Errors carry no stack trace (see `src/lib/app-errors.ts`). |
| **Pagination** | Question bank: keyset cursor (`cursor` = last id, `limit` ≤ 50 student / ≤ 500 admin). Per-student lists: `limit` ≤ 50, `offset` ≤ 10,000, response `nextOffset` (null on the last page). |
| **Question content shape** | Question fields keep the database names (`question_text`, `option_a`…`option_d`, `correct_answer`, `rationale`). Students never receive `correct_answer`/`rationale` before submission. |

| `statusCode` | `code` | Meaning |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Input failed validation |
| 401 | `UNAUTHORIZED` | Missing/invalid token |
| 403 | `FORBIDDEN` | Not an admin |
| 404 | `NOT_FOUND` | Missing, or not owned by the caller (the two are indistinguishable on purpose) |
| 402 | `PAYMENT_FAILED` | Payment verification route only: the provider did not confirm the payment |
| 409 | `CONFLICT` / `SESSION_CLOSED` | Active session exists, duplicate report, session already closed |
| 429 | `LIMIT_REACHED` | Tier, daily, bookmark or report limit |
| 500 | `INTERNAL` | Unexpected failure |
